Sistema distribuído de controle de tráfego com Raspberry Pi e ESP32 Link para o cabeçalho

Tipo: Projeto acadêmico

Problema: Controlar e monitorar cruzamentos de trânsito usando Raspberry Pi, ESP32, comunicação local e controle físico por GPIO.

O que foi feito: Implementação de controle de semáforos, leitura de botões de pedestre, debounce, execução concorrente com threads, comunicação UART, protocolo simplificado, wrapper MODBUS modificado e reestruturação para arquitetura com processo central e processos distribuídos. O projeto também envolveu sockets TCP/IP locais, sinais Linux e finalização limpa de processos.

Stack: C++, Raspberry Pi, ESP32, WiringPi, GPIO, UART, RS485, MODBUS RTU, TCP/IP, sockets, threads, mutex, condition variable, fork(), waitpid(), SIGINT, Makefile e Linux.

Valor técnico: Experiência integrando software, hardware, comunicação serial, concorrência e arquitetura distribuída em um sistema com restrições físicas.

Simulação C++/OpenMP migrada para CUDA Link para o cabeçalho

Tipo: Projeto prático e estudo aplicado

Problema: Adaptar uma simulação científica originalmente executada em CPU para uma versão CUDA, lidando com diferenças de memória, paralelismo e ambiente de execução.

O que foi feito: Criação de kernels CUDA, substituição de loops OpenMP, troca de estruturas baseadas em std::vector por ponteiros na GPU, uso de cudaMalloc, cudaFree, cudaDeviceSynchronize, atomicAdd, inicialização de partículas, deposição de densidade, redução de histogramas, solver manual e adaptação do código para evitar timeout no LeetGPU.

Stack: C++, OpenMP, CUDA, Eigen, Raylib, kernels CUDA, memória de GPU, método de Thomas, atomicAdd e profiling de execução.

Valor técnico: Aprendizado prático de que portar código CPU para GPU exige mudança de algoritmo, layout de dados, granularidade, sincronização e estratégia de medição.

Diagnóstico de CI com GitHub Actions e submódulos Link para o cabeçalho

Tipo: Investigação técnica

Problema: Pipeline de GitHub Actions falhava ao clonar submódulos por erro 403, indicando ausência de permissão de escrita/acesso.

O que foi feito: Análise de log de runner, investigação do checkout de submódulos privados e identificação do problema como questão de token, permissões e acesso a repositórios dependentes.

Stack: GitHub Actions, actions/checkout@v4, Git, submodules, tokens, permissões de repositório, Ubuntu runner, Docker Compose e logs de pipeline.

Valor técnico: Capacidade de ler falhas de CI, separar erro de código de erro de infraestrutura e apontar a causa provável com base em logs.
