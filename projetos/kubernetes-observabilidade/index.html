Projeto acadêmico/experimental

Observabilidade em Kubernetes com Prometheus e Grafana

Cluster local com monitoramento, testes de carga e análise de cenários estáveis e instáveis.

  • Kubernetes
  • Kind
  • Docker
  • Helm
  • Prometheus
  • Grafana
  • Locust

  • PostgreSQL
  • Node.js

Contexto Link para o cabeçalho

Projeto acadêmico/experimental para estudar implantação local, observabilidade e comportamento de uma aplicação distribuída sob carga.

Problema Link para o cabeçalho

Era necessário executar serviços em Kubernetes local e observar estabilidade, uso de CPU, crashes e downtime em cenários de carga.

Minha atuação Link para o cabeçalho

Configurei um cluster Kind com control-plane e workers, deploy de serviços, monitoramento com kube-prometheus-stack, dashboards com Grafana e execução de testes com Locust.

Solução Link para o cabeçalho

O ambiente foi montado em camadas: cluster local, serviços da aplicação, banco, monitoramento e ferramenta de carga. A análise comparou cenários estáveis e instáveis para identificar comportamento sob pressão.

Arquitetura Link para o cabeçalho

Locust → serviços Node.js/gRPC em Kubernetes → PostgreSQL.

Prometheus coleta métricas do cluster e dos serviços. Grafana exibe painéis para análise durante os testes.

Resultado Link para o cabeçalho

  • Teste com 200 usuários permaneceu estável.
  • Teste com 400 usuários revelou instabilidade, crash, queda de CPU e downtime.
  • O ambiente permitiu observar indisponibilidade e comportamento de serviços em cluster local.

Tecnologias Link para o cabeçalho

Kubernetes, Kind, Docker, Helm, Prometheus, Grafana, Alertmanager, kube-prometheus-stack, Locust, gRPC, PostgreSQL, Node.js e Linux.

Aprendizados Link para o cabeçalho

  • Teste de carga precisa ser analisado junto com métricas do cluster.
  • Um cenário estável em uma carga pode falhar rapidamente em outra.
  • Observabilidade ajuda a separar sintomas de indisponibilidade, consumo de recursos e falhas de serviço.
