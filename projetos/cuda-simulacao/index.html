Estudo aplicado

Simulação C++/OpenMP adaptada para CUDA

Adaptação de uma simulação científica de CPU para GPU, com revisão de memória, paralelismo e execução.

  • C++
  • OpenMP
  • CUDA
  • Eigen
  • Raylib

Contexto Link para o cabeçalho

Estudo aplicado de computação paralela e desempenho em uma simulação científica originalmente executada em CPU.

Problema Link para o cabeçalho

O código precisava ser adaptado para CUDA, lidando com diferenças entre paralelismo em CPU e GPU, layout de dados, sincronização e ambiente de execução.

Minha atuação Link para o cabeçalho

Criei kernels CUDA, substituí loops OpenMP, troquei estruturas baseadas em std::vector por ponteiros na GPU e usei cudaMalloc, cudaFree, cudaDeviceSynchronize e atomicAdd.

Também adaptei inicialização de partículas, deposição de densidade, redução de histogramas, solver manual e execução em ambiente LeetGPU.

Solução Link para o cabeçalho

A adaptação tratou o código como uma mudança de arquitetura, não apenas como troca de diretivas. O foco foi mover dados e operações para um modelo compatível com GPU e analisar custos de sincronização.

Arquitetura Link para o cabeçalho

CPU prepara parâmetros e buffers → GPU executa kernels de partículas, densidade e redução → CPU coordena sincronização e saída.

Resultado Link para o cabeçalho

  • Simulação adaptada para execução CUDA.
  • Diferenças de memória e granularidade entre CPU e GPU investigadas.
  • Timeout em ambiente LeetGPU analisado como consequência de custo de kernels, malha e sincronizações.

Tecnologias Link para o cabeçalho

C++, OpenMP, CUDA, Eigen, Raylib, kernels CUDA, memória de GPU, método de Thomas, atomicAdd e profiling de execução.

Aprendizados Link para o cabeçalho

  • Portar CPU para GPU pode exigir mudança de algoritmo e layout de dados.
  • Muitos kernels pequenos podem custar mais do que aparentam.
  • Medição é necessária para separar ganho real de paralelismo aparente.
