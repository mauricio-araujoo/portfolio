Aplicação web com Spring Boot e Stripe

Evolução de um sistema administrativo com pagamentos, relatórios e regras de negócio.

  • Java
  • Spring Boot
  • Thymeleaf
  • Oracle
  • Stripe
  • MapStruct
  • OpenPDF

Contexto Link para o cabeçalho

Projeto ligado a uma experiência profissional parcialmente confirmada, envolvendo manutenção e evolução de uma aplicação web administrativa.

Problema Link para o cabeçalho

A aplicação precisava evoluir funcionalidades internas, regras de negócio, templates, fornecedores, lotes, relatórios e integração de pagamento.

Minha atuação Link para o cabeçalho

Atuei no desenvolvimento e ajuste de páginas com Spring Boot e Thymeleaf, modais, filtros, paginação, regras de exclusão, geração de relatório PDF e integração com Stripe.

Também houve investigação de problemas de compilação, mapeamento entre DTOs e entidades, invoice items, metadata, webhooks e uso de ambiente auxiliar com Flask e ngrok.

Solução Link para o cabeçalho

O trabalho foi organizado em entregas funcionais menores: correção de fluxos existentes, implementação de telas administrativas, ajuste de persistência relacional, geração de documentos e integração com serviços externos.

Arquitetura Link para o cabeçalho

Usuário administrativo → telas Thymeleaf → controllers Spring Boot → serviços de regra de negócio → Oracle DB.

Fluxos de pagamento usam Stripe SDK, webhooks e metadata para conectar eventos externos ao sistema.

Resultado Link para o cabeçalho

  • Integração de pagamento implementada.
  • Relatório PDF gerado.
  • Funcionalidades administrativas evoluídas com filtros, paginação e modais.
  • Correções aplicadas em mapeamentos, builds e regras de exclusão.

Tecnologias Link para o cabeçalho

Java, Spring Boot, Spring Security, Thymeleaf, Oracle DB, MapStruct, Stripe Java SDK, Flask, ngrok, HTML, CSS, JavaScript, Git, GitHub, OpenPDF/iText e Tomcat.

Aprendizados Link para o cabeçalho

  • Integrações de pagamento exigem atenção a eventos, metadata e reconciliação entre sistemas.
  • Relatórios e telas administrativas precisam acompanhar regras de negócio e persistência.
  • Problemas de mapeamento e build costumam exigir leitura cuidadosa do fluxo entre DTOs, entidades e templates.
